# Sepia

Сайты-заглушки + скрипт провижинга standalone VLESS+Reality **selfsteal**-ноды для Remnawave.

Сайт служит реальной страницей за заглушкой: Xray форвардит на него непрошедший
Reality-авторизацию трафик, и активный пробер видит обычный сайт.

Выбор сайта — переменная `SITE` (вопрос в меню), по умолчанию **arclayer**:

- **arclayer** — многостраничный лендинг Arclayer (вымышленный web3-инфра бренд): главная
  + Network/Build/Company + 404, локализация EN/RU, дот-глобус. Папка `site/`. Основной.
- **sepia** — одностраничная «Сепия» (лендинг цветокора видео). Папка `site-sepia/`.
- **racelive** — реальное приложение RaceLive (Next.js+FastAPI, ~4 ГБ RAM), разворачивается
  `deploy-racelive.sh` поверх. См. раздел ниже.

## Структура

```
site/                 # Arclayer (основной decoy, -> /var/www/decoy)
  index.html  network.html  build.html  company.html  404.html  robots.txt
  assets/             # app.css, app.js, favicon.svg (общие для всех страниц)
site-sepia/           # «Сепия» (альтернативный одностраничный decoy)
provision-node.sh     # провижинг ноды (всё кроме remnanode)
tune-kernel.sh        # тюнинг ядра (BBR+cake, swap, nofile)
node-check.sh         # проверка ноды: меню, CPU, сеть, блокировки (РФ), гео IP, пик против тишины
stats/                # VictoriaMetrics на сервере панели — приёмник статистики node-check
deploy-racelive.sh    # вариант SITE=racelive (черновик)
```

## Что делает provision-node.sh

Ставит и настраивает **всё, кроме самого remnanode**:

1. nginx-заглушку на `127.0.0.1:8081` (http2 + TLS1.3), decoy из `site/`
2. сертификат Let's Encrypt (HTTP-01 webroot, авто-продление)
3. nftables-фаервол:
   - наружу только `80` и `443`
   - `NODE_PORT` (2222) — только с IP панели
   - SSH — только с `ADMIN_IP`
   - всё остальное — `RST` (как будто порт закрыт)
   - безопасное применение с авто-откатом (`nft flush` через 120с, если не подтвердить)
4. генерацию ключей **X25519 + shortId** (для вставки в Config Profile панели)

## Использование

На свежем NL-сервере (Debian/Ubuntu):

```bash
git clone https://github.com/oINCLUDEo/Sepia.git
cd Sepia
sudo DOMAIN=studio.ulya.space ./provision-node.sh
```

Переопределяемые параметры (env, есть дефолты под парк `ulya.space`):

| env | дефолт | смысл |
|-----|--------|-------|
| `DOMAIN` | — (обязательно) | поддомен ноды = SNI |
| `EMAIL` | `ulya-tech@yandex.com` | для Let's Encrypt |
| `PANEL_IP` | `51.89.110.208` + `179.253.100.109` (панель переезжает 15.11) | доступ к NODE_PORT |
| `ADMIN_IP` | `95.104.206.188` | SSH-доступ (динамический — обновлять!) |
| `NODE_PORT` | `2222` | control-порт remnanode |
| `STUB_PORT` | `8081` | локальный порт заглушки |

После скрипта:
1. поставить **remnanode** штатно (NODE_PORT + SECRET_KEY из панели);
2. вписать выведенные `privateKey/publicKey/shortId/serverNames/target` в
   Config Profile → Inbound, привязать Host (`address` = **домен**) к ноде, добавить в Squad.

## Предварительно

- A-запись `DOMAIN` → IP ноды, **DNS-only** (без Cloudflare-proxy).
- Держать открытой консоль хостера (VNC) при первом применении фаервола.
- `ADMIN_IP` динамический: при смене IP обновить правило и перезапустить `nft -f /etc/nftables.conf`
  (или перейти на Tailscale/Headscale — SSH только из mesh).

## Тюнинг ядра — tune-kernel.sh

Отдельный скрипт, можно гонять и на новых, и на уже работающих нодах
(из `provision-node.sh` вызывается при `TUNE=1` или ответе `y` на вопрос).

```bash
sudo bash tune-kernel.sh                              # cake, IPv6 off, swap 1G
sudo QDISC=fq NO_IPV6=0 SWAP_SIZE=2G bash tune-kernel.sh
```

Что делает:
- BBR + qdisc (`cake` по умолчанию, `QDISC=fq` легче по CPU); qdisc держится после
  перезагрузки через `rw-qdisc.service`
- буферы/очереди/TIME_WAIT/conntrack под тысячи соединений, `tcp_mtu_probing`
- hardening: анти-спуфинг, ICMP, ptrace, ASLR
- IPv6 off + вычищает `listen [::]` из nginx
- `ip_forward=0`, но только если нет контейнеров в bridge-сети (иначе оставляет 1)
- swap-файл, если свопа нет; `swappiness=10`
- `nofile=1048576` для контейнеров (`default-ulimits` в `/etc/docker/daemon.json`)

Всё пишется в `/etc/sysctl.d/99-rw-node.conf`, `/etc/modules-load.d/rw-node.conf`;
бэкапы изменённых файлов — `/root/rw-tune-backup/<дата>/`. **Не для сервера панели**
(скрипт сам откажется, если видит контейнер `remnawave/backend`).

## Проверка ноды — node-check.sh

```bash
sudo bash node-check.sh                 # меню
sudo bash node-check.sh full            # полный прогон ~3 мин (NO_IPERF=1 — без нагрузки на канал)
sudo bash node-check.sh install         # таймеры: снимок каждую минуту, ночью — самообновление и полная проверка
sudo bash node-check.sh report          # через сутки-двое: средние по часам, пик против тишины
sudo bash node-check.sh stats           # выгрузка в VictoriaMetrics (URL, логин, пароль, имя ноды)
```

- **full**: система и настройки (BBR, IPv6, Xray), нагрузка сейчас, sysbench 1 поток + steal под
  полной нагрузкой, пинг/потери, iperf3 до РФ в обе стороны, страна IP по ipinfo, ip-api, ChatGPT
  (Cloudflare) и YouTube. В конце — список замечаний.
- **Нода в РФ** определяется сама (RU=1/RU=0 — принудительно): вместо пинга до РФ — пинг до Европы,
  плюс «заморозка» TLS на 16–20 КБ до Hetzner/OVH/Vultr (ТСПУ), сайты, которые режет DPI, скорость
  скачивания из Европы.
- **minute** (таймер systemd каждую минуту): CPU/steal, трафик, соединения, ретрансмиты, conntrack, CPU Xray, RTT (до РФ,
  у РФ-ноды — до Европы). Не ждёт 10 секунд, а берёт разницу счётчиков ядра с прошлого запуска — точное среднее за
  минуту, нода видна всё время; ~3 с на запуск. Таймер не зависит от службы cron (на части образов она выключена).
  Без systemd — cron. **quick** — то же разово, замером 10 секунд.
- **daily** (таймер ночью, 03:15–05:15 МСК): самообновление из git (не вышло — событие на дашборде). Сначала нода
  смотрит, прошла ли новая версия проверку на GitHub (`.github/workflows/check.yml`): упала — не обновляется
  (событие «не стала обновляться»), ещё идёт — ждёт следующей ночи, GitHub API недоступен — обновляется, полагаясь
  на самопроверку; `UPDATE_REQUIRE_CI=1` в `/etc/rw-node-check.conf` — без зелёной проверки не обновляться вовсе. Новая версия сначала проходит самопроверку (`bash -n` и настоящий замер без отправки, режим `selftest`);
  не прошла — откат на прежний коммит (`git reset --keep`, локальные правки не трогаются) и событие «не прошла
  самопроверку» в журнале; причина — в `/var/log/rw-node-check-actions.log`. проверка таймера, полная проверка с iperf3 (`NIGHT_FULL=0` / `NIGHT_IPERF=0` — выключить), CSV — 14 дней.
  Пока идёт, минутные снимки пропускаются, чтобы нагрузка проверки не попала в статистику.
- **Сервисы** (раз в 30 минут): нода сама открывает YouTube, Instagram, ChatGPT и Claude (API: 401 — доступ есть,
  403 — регион закрыт), Telegram, WhatsApp, Discord, X, Spotify, Netflix и российские — Госуслуги, Сбер, Яндекс, VK,
  Ozon, WB; на дашборд — код ответа и время (`node_svc_code`, `node_svc_ms`, метка `svc`). Все запросы параллельно, до 8 с.
- **Автотрассировка**: если потери до цели пинга от 2% или ретрансмиты от 10% при трафике, нода сама делает
  `mtr` (не чаще раза в 30 минут) — хопы с потерями и задержкой (`node_trace_*`), событие в журнале; дашборд
  показывает, где начинаются потери: у хостера, по пути или у получателя. Вручную: `sudo bash node-check.sh trace [цель]`.
- **Безопасность и ОС** (раз в сутки, ночью): обновления (и из них безопасности), нужна ли перезагрузка, автообновления,
  SSH по паролю и root, фаервол (nftables/iptables с политикой drop), какие порты слушают снаружи (`node_sec_*`).
  Вручную: `sudo bash node-check.sh security`.
- **Репутация IP** (раз в 3 часа): IP в списках Spamhaus, Barracuda, SpamCop, DroneBL (через системный DNS; список,
  отказавший публичному резолверу, не учитывается) и капча Google (`node_rep_*`: 1 — в списке, 0 — чисто).
- **Маскировка** (каждые 10 минут, и в полной проверке): нода стучится сама к себе на 443 с SNI своего домена — как
  активный пробер — и проверяет, что заглушка отвечает как сайт, отдаваемый сертификат проходит проверку и сколько
  дней ему осталось, включено ли автопродление certbot. Чинит сама безопасное: nginx лежит — поднимает; сертификат
  продлили, а nginx отдаёт старый — перезагружает; осталось меньше 20 дней — ночью пробует `certbot renew`. Домен
  заглушки берётся из `decoy.conf` (provision-node.sh) или Let's Encrypt, либо `NODE_DOMAIN` в конфиге; у нод с маской
  на чужой домен (режим 3) проверять нечего.
- В каждом снимке уходит версия скрипта (коммит и его дата): дашборд показывает, кому нужно обновление.
  Старые установки (раз в 15 минут, без самообновления) переводятся один раз: `cd /root/Sepia && git pull && bash node-check.sh install`.
- **report**: таблица по часам суток, пиковый час против самого тихого и что деградирует в пик.

Чужие скрипты не качает (в отличие от multitest). Наружу уходят только метрики в свою
VictoriaMetrics, если настроить. Настройки ноды: `/etc/rw-node-check.conf` (600).

### Статистика всех нод — stats/

На сервере панели: `cd stats && cp .env.example .env` (задать `VM_PASS`), `docker compose up -d` —
контейнер `node-stats` в сети `remnawave-network`. В `/opt/remnawave/caddy/Caddyfile` в блок
`panel.ulya.space` добавить `handle /node-stats/* { reverse_proxy node-stats:8428 }` (остальное — в
`handle { ... }`). Отдельный поддомен не годится: `DOCKER-USER` не пускает Let's Encrypt, серт не выпустится.
Запись от нод идёт через шлюз `vmauth` (контейнер `node-stats-gw`, `stats/vmauth.yml`):
`https://panel.ulya.space:9443/node-stats/write`, логин `writer`, пароль `VM_WRITE_PASS`. Шлюз пропускает только
запись, TLS — сертификатом Caddy (том `caddy-ssl-data`), служебные страницы закрыты ключом `VM_PASS`.
У самой VictoriaMetrics пароля нет (она только в docker-сети и на 127.0.0.1): чтение (дашборд, vmui) на 443
пускает Caddy после проверки в `node-auth` (см. «Вход в дашборд» ниже).
Белый список IP нодам больше не нужен — `FIREWALL=0` в `/etc/rw-node-sync.conf` снимает правила `rw-sync`.

Дашборд (`stats/dashboard/`, контейнер `node-dash`): `https://panel.ulya.space/node-stats/dash/`, вход логином
`VM_USER` и паролем `VM_PASS`. Открытый с диска `index.html` показывает демо-данные. Файлы: `index.html` — разметка,
`assets/app.css`, `assets/*.js` (core, data, demo, charts, render, drawer, events, hero, app — подключаются по порядку).

**Вход в дашборд — по cookie** (`stats/auth/auth.py`, контейнер `node-auth`, только стандартная библиотека Python).
Пароль проверяет сервис и ставит cookie `ulya_stats` (HttpOnly — скрипты страницы её не видят, Secure, SameSite=Strict,
30 дней с галкой «Запомнить», иначе до закрытия браузера). Caddy перед каждым запросом к данным и vmui спрашивает
сервис (`forward_auth`). Не больше 10 неудачных попыток за 15 минут с одного IP. `curl -u node:VM_PASS` по-прежнему
работает. Сменить `AUTH_SECRET` или `VM_PASS` — разлогинить все устройства. После 10 неудачных попыток за 15 минут с одного IP
вход закрыт для этого IP — и через форму, и через Basic.

**Снаружи — только чтение.** Caddy отвечает 403 на запись, импорт, удаление и служебные адреса VictoriaMetrics даже
после входа (`Caddyfile.snippet`), а сама VictoriaMetrics требует для удаления, снимков и служебных страниц отдельный
ключ `VM_ADMIN_KEY` из `.env` (его нет ни у дашборда, ни у нод; нужен только `rename-node.py`). Переход со старого `basic_auth`:

```bash
cd /opt/Sepia && git pull && cd stats
echo "AUTH_SECRET=$(openssl rand -hex 32)" >> .env
docker compose up -d                       # поднимет node-auth
# в /opt/remnawave/caddy/Caddyfile заменить прежний блок node-stats на stats/Caddyfile.snippet, затем:
docker exec <контейнер caddy> caddy reload --config /etc/caddy/Caddyfile
```

**Переименовали ноду** (node-check, меню → 6) — история за прошлые дни осталась под старым именем. Перенести на
сервере панели: `python3 stats/rename-node.py --list` (какие имена есть), затем
`python3 stats/rename-node.py СТАРОЕ НОВОЕ --dry-run` и без `--dry-run`. Повторный запуск точки не задваивает.

- **Разделы вкладками**: Обзор (шапка и ноды) · Сутки · Графики · Карта · Ёмкость · Отчёт — страница короткая,
  листать почти не нужно. На телефоне вкладки — панелью снизу. Ссылка на раздел: `…/dash/#v=capacity`;
  клавиши `1`–`6`. Точка на вкладке — там есть проблемы или советы.
- **Поиск** (`Ctrl+K` или `/`, кнопка-лупа в шапке): нода по имени, стране, хостеру или IP, разделы, действия
  (добавить заметку, сменить тему, скачать отчёт).
- **Состояние иконкой и цветом** (иконки Lucide, ISC — спрайтом прямо в `index.html`): ✓ норма, ! замечание,
  ✕ плохо, часы — молчит, щит — маскировка, запрет — похоже заблокирован; различимо и без цвета.
- **Шапка**: живая планета — ночная Земля точками (маска суши Natural Earth, общественное достояние, `assets/earth-mask.js`),
  атмосфера по краю, на ней ноды цветом состояния и пути «мост → выход» дугами с бегущим светом; планета
  покачивается вокруг Европы. Рисуется только когда шапка на экране; «уменьшить движение» — статичный кадр.
  Под ней: трафик сейчас, пользователей онлайн по всей панели
  (уникальных — из статистики Remnawave, с балансировщиком сумма по нодам больше людей), пик за сутки, сколько нод с замечаниями, самый загруженный канал
  (текущая отдача / лучший iperf из полной проверки). Плашки состояний под ней фильтруют карточки.
- **Ноды**: группы «Выходы» и «Мосты в РФ»; отключённые в панели и ноды без статистики — свёрнутым списком в конце.
  Замолчавшая нода показывает последние значения серым. Вид «Карточки / Таблица». Нажатие на ноду открывает
  панель со всеми метриками (память, conntrack, CPU Xray, джиттер, входящий трафик, DPI), графиками и
  доступностью; ссылка вида `…/dash/#node=DE-Aeza-2` открывает её сразу.
- **География**: карта точками, масштаб — по области, где стоят ноды. Выходы — по странам (размер — онлайн, цвет —
  состояние); каждый мост — отдельно, со своим цветом линий. Линии — только настоящие пути «мост → выход»: `rw-sync.py`
  берёт их из исходящих (outbounds) конфиг-профилей панели и сопоставляет адреса с нодами (проверить:
  `rw-sync.py --dry-run` печатает «Связи мостов»). Наведение подсвечивает пути моста или выхода, нажатие открывает ноду.
- **Маскировка**: статус «заглушка не отвечает» / «сертификат не проходит проверку» / «сертификат: осталось N дн»,
  раздел в карточке ноды, колонка «Серт.» в таблице, отрезки и события в «Сутках»; алерты NodeDecoyDown, NodeCertInvalid, NodeCertExpiring.
- **Похоже, IP заблокирован**: онлайн ноды упал меньше чем до 30% от того же часа вчера (было хотя бы 20 человек),
  по сети в целом падения нет (больше 70%), нода включена и панель её видит. Статус на карточке, отрезок в «Сутках»,
  алерт `NodeMaybeBlocked` (держится 15 минут). Пороги — `BLOCK` в `assets/core.js` и в `stats/alerts/rules.yml`.
- **Онлайн и «на связи»**: у ноды — сколько клиентов сейчас на связи с ней (из панели). С балансировщиком (автовыбор
  в клиенте) одно устройство держит связь сразу с несколькими нодами, поэтому это не число людей, а охват ноды —
  для детектора блокировки как раз то, что нужно. Людей онлайн — в шапке, из общей статистики панели.
  Если `rw-sync.py` больше 15 минут не присылал справочник — плашка «Данные панели устарели», показывается последнее известное.
- **Версии node-check**: колонка в таблице, строка в карточке ноды и плашка над нодами — у кого старый скрипт без
  самообновления (обновить вручную один раз) и кто обновится ночью сам.
- **Сутки**: полоса состояний каждой ноды за 24 часа по 15 минут (норма / замечание / плохо / молчала / панель не
  видела) и журнал событий: «21:15–22:30 · DE-Aeza-2 · ретрансмиты до 7,2% · 1 ч 15 мин». Считается на странице из
  тех же снимков и порогов, отдельный сервис не нужен; алерты для этого включать не обязательно. Там же — что ноды
  сделали сами: обновились, не смогли обновиться, увеличили conntrack, перезапустили таймер.
- **Динамика** (сутки / неделя / месяц), **часы пик**, **полные проверки**, **хостеры за 30 дней** (хостер — из
  имени ноды: `DE-Aeza-2` → Aeza; средний steal, ретрансмиты, потери, худшая доступность, цена, «за ТБ» и
  «за 100 Мбит/с пика»).
- **Заметки на графиках** («Графики» → «Заметка», или в панели ноды): «сменил хостера», «обновил Xray» — метка на всех
  графиках и строка в «Сутках»; что ноды сделали сами (обновились, conntrack, сертификат) — серыми метками на графике
  ноды. Пишет `node-auth` в VictoriaMetrics (`node_note_n`), удаляет — с `VM_ADMIN_KEY`; хранятся 180 дней.
  После обновления: `docker compose up -d auth` (ему нужны `VM_URL` и `VM_ADMIN_KEY` из docker-compose.yml).
- **Ёмкость**: прогноз — прямая по дневным пикам за 30 дней: когда пик дойдёт до 90% канала (лучший iperf из полной
  проверки); советы балансировщику — какой выход разгрузить и какой свободнее (за тем же мостом); мост на пределе;
  сколько ТБ нода отдала за 30 дней. Цена ноды задаётся на ней: `sudo bash node-check.sh price 6.5 EUR` (0 — убрать).
- **Риск для соседей**: если у ноды похоже заблокирован IP (сейчас или за сутки), ноды в той же подсети /24
  получают предупреждение (их часто блокируют пачкой), выходы того же хостера — пометку «следите за онлайном».
- **Отчёт за месяц** (текущий и 5 прошлых): доступность и простой нод, пик сети, отдано ТБ, онлайн в пик, steal,
  ретрансмиты, потери, что ноды делали сами, заметки. «CSV» — для Excel (`;`, десятичная запятая), «PDF / печать» —
  печатается только отчёт.
- **Доступ**: какие сервисы открываются через каждую ноду — логотипами плитками, как значки приложений
  (Simple Icons — CC0; Яндекс — Font Awesome Brands, CC BY 4.0; Сбер и WB — Arcticons, CC BY-SA 4.0; у Госуслуг и Ozon
  открытых логотипов нет — буквами). Выходу важны зарубежные сервисы, мосту в РФ — российские напрямую; закрытое в РФ
  на мосту — серым «ожидаемо», а не аварией. Сводка «ChatGPT не открывается через …», таблица репутации IP.
  На карточке ноды — строка значков нужной ей группы, в панели ноды («Проверки») — все с пояснением.
- **Безопасность** (вкладка «Доступ»): таблица по нодам — фаервол, SSH, root, обновления, автообновления,
  перезагрузка, порты; в карточке ноды («Проверки») — чек-лист и команда, как исправить каждое замечание.
  Там же — **трассировка**, если нода её делала: таблица хопов и вывод, на каком участке проблема.
- **Выключить хосты заблокированной ноды**: в карточке ноды с «похоже, IP заблокирован» — кнопка; дашборд находит
  её хосты в Remnawave (привязанные к ноде или ведущие на её IP или домен заглушки), показывает список и после
  подтверждения выключает их — пользователи перестают получать ноду в подписке; нода, профиль и Squad не меняются.
  «Включить обратно» — той же кнопкой; каждое действие — заметкой на графиках. Делает `node-auth` токеном Remnawave:
  `RW_TOKEN` в `stats/.env` (можно тот же, что у rw-sync), при другом имени контейнера панели — `RW_API`;
  затем `docker compose up -d auth`. Без токена кнопка скажет, что не настроено.
- **Новая нода** (кнопка в «Нодах» или поиск → «Новая нода»): имя, роль, поддомен, IP, цена — готовые команды по шагам
  с кнопкой «Скопировать» (DNS, provision-node.sh, tune-kernel.sh, node-check со статистикой и ценой, что сделать в панели);
  потом дашборд сам ждёт первый снимок и пишет «подключилась». Пароль записи в команде — заглушкой.
- **Полоса «Сейчас»** в шапке: что не так прямо сейчас (до трёх нод, самое серьёзное первым, «ещё N» — фильтр), всё хорошо — последнее событие; без прокрутки. В журнале не показываются провалы короче 30 минут и первый час новой ноды — это настройка, а не аварии;
  разделы переключаются плавно (View Transitions).
- **Живая карта**: по линиям «мост → выход» бегут точки — чем больше трафика, тем их больше и быстрее; путь к
  проблемной ноде мерцает красным, проблемная точка расходится кольцом. С «уменьшить движение» в системе — без анимации.
- Пороги «замечание / плохо» — одна таблица `TH` в `index.html`; те же «плохо» — в `stats/alerts/rules.yml`.
- **Ни одного внешнего запроса**: шрифты (Lack, Carlito, Alan Sans — OFL) в `fonts/`, флаги (flag-icons, MIT) в
  `flags/`, маска суши для планеты вшита. `no-referrer` и CSP `default-src 'self'` прописаны в самой странице, так что адрес
  панели и IP админа не уходят Google и CDN флагов.

**Алерты в Telegram** (`stats/alerts/`): vmalert считает правила по тем же метрикам, Alertmanager шлёт в чат.

```bash
cd /opt/Sepia/stats
cp alerts/alertmanager.yml.example alerts/alertmanager.yml   # вписать chat_id служебного чата
printf '%s' '123456:ABC...' > alerts/tg_token && chmod 644 alerts/tg_token   # токен бота
docker compose --profile alerts up -d
```

Что приходит: похоже, IP ноды заблокирован; нода молчит больше 10 минут (старый node-check — 30); ретрансмиты выше 10% дольше часа; steal выше 15%, CPU выше 90%,
потери выше 2%, память выше 92% дольше 30 минут; conntrack выше 90%; панель не видит включённую ноду;
`rw-sync.py` 30 минут не обновлял справочник. Когда проблема уходит — сообщение «прошло».

**Как читать ретрансмиты.** Это доля TCP-сегментов, отправленных повторно, по всей ноде — и к пользователям, и от
Xray к сайтам. С BBR и мобильными клиентами 2–5% — обычное дело: BBR сам прощупывает канал, мобильная сеть и ТСПУ теряют
пакеты, на что нода не влияет. Замечание — от 5%, «плохо» — от 10%, алерт — выше 10% дольше часа; при трафике меньше
1 Мбит/с не считаются. Сами по себе ретрансмиты не значат, что пользователям плохо: смотреть вместе с пингом и скоростью.
Что делать при стабильно высоких: `node-check.sh report` (растёт только в пик → упирается канал или хостер; держится
всегда → плохой маршрут), `mtr -rwzc 200 <IP в РФ>` с ноды, сравнить ноды одного хостера в таблице «Хостеры».

**Conntrack** (таблица соединений ядра; нужна фаерволу ноды). По умолчанию запись живёт 5 суток, мобильные клиенты
пропадают без закрытия — таблица забивается, при 100% новые подключения молча отбрасываются. `tune-kernel.sh` ставит
размер по памяти (до 1 млн записей) и срок жизни 2 часа (безопасно: Xray сам закрывает соединение после 5 минут
тишины). Кроме того, `node-check` в каждом снимке при заполнении от 80% сам удваивает таблицу (не больше четверти
памяти) и пишет это в `/var/log/rw-node-check-actions.log`.

Синхронизация с панелью (`stats/rw-sync.py`, на сервере панели, cron раз в 5 мин): берёт ноды из API
Remnawave, пускает их IP на 443 в `DOCKER-USER` (правила с пометкой `rw-node-sync`, лишние убирает) и пишет
справочник `node_panel_*` (имя, флаг, IP, связь, клиентов на связи) и общую статистику панели
`node_panel_stats` (онлайн сейчас / за сутки / за неделю, всего пользователей) — дашборд показывает ноды под именами из панели,
а ноды без node-check — карточкой «нет статистики». Установка: `python3 /opt/Sepia/stats/rw-sync.py --install`
(спросит API-токен Remnawave), проверка без изменений: `--dry-run`. Ноды сопоставляются по IP: node-check
шлёт метку `ip` (свой внешний IPv4).

На нодах: меню → 6 (URL `https://panel.ulya.space:9443/node-stats/write`, логин `writer`, `VM_WRITE_PASS`), затем
меню → 5 (сбор). Графики — `https://panel.ulya.space/node-stats/vmui`, метрики `node_quick_*{node="..."}`
(каждые 15 мин) и `node_full_*` (после полных прогонов), например `node_quick_tx_mbps`,
`node_quick_cpu_st`, `node_quick_rtt_ms`.
